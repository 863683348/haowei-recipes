# 食谱富媒体 CTR 实验方案（P2-#8，2026-09-08）

> 背景：食谱富媒体占全站展示 64%（2,904/4,548）、点击 23/27（85%）——Recipe JSON-LD 已充分激活，是点击引擎。
> 但富媒体 CTR 0.79% 仍低于菜谱行业（2-5%），主因是排名偏深（38.3）。对进入前 20 的页，首图 appetizing 程度直接决定富媒体 CTR。
> 本方案：对已进前 20 的食谱页做首图质量 A/B，用数据验证「图片=CTR」假设。

---

## 1. 实验对象（已进前 20 / 高展示近胜利的菜谱页）

| 页面 | 排名 | 现状 |
|---|---|---|
| /en/recipes/tingzai-congee（艇仔粥） | 8.9（1 点击） | 1 张 hero 图 |
| /en/recipes/garlic-romaine（蒜蓉油麦菜） | 7.5 | 1 张 hero 图 |
| /en/recipes/iron-pot-fish-stew | 4.0（1 点击） | 1 张 hero 图 |
| /en/recipes/suan-luo-bo（酸萝卜） | 4.7 | 1 张 hero 图 |
| /en/recipes/onion-beef-stir-fry | 43.8（2 点击，点击王） | 1 张 hero 图 |

## 2. 假设与变量

- **H1**：首图改为「成品特写 + 热气/汁水光泽」风格，富媒体 CTR 提升 ≥50%。
- **H2**：页面内步骤图从 1 张扩到 3-5 张，页面停留与内链点击提升（间接信号）。
- 控制变量：title/description 不变（P0-1 已单独做文案收割），只换图。

## 3. 执行方案（零成本约束）

1. **选图渠道**：即梦AI（每日 60 张免费额度）生成每道菜 3 张候选首图：
   - A：现状 hero（已有）
   - B：成品俯拍 + 自然光 + 蒸汽（appetizing 首图）
   - C：成品特写 + 酱汁流动/脆皮细节
2. **每道菜 1 张 B 图替换** hero（图片 1200×630，webp，替换 `recipe.image`），**分两批**（3 道先上、2 道后上），避免同批全量换图混淆归因。
3. **GSC 观测**（实验窗口 4 周）：
   - 每页「食谱富媒体」CTR 前后对比（SERP 特征维度）
   - 点击/展示/排名（页面维度）
4. **判定**：B 图页 CTR 相对提升 ≥50% → 全站推广；<20% → 保留 A，转向排名/外链投入。

## 4. 步骤图（H2）扩展

- 每道菜补 3 张步骤图（切配/下锅/成品），插到步骤区（需改菜谱页组件支持多图 + `image` 数组 JSON-LD）。
- **本轮不做**：涉及组件改造 + 图片资源量大，标记为 P2 待资源。先验证 H1（首图 A/B）成本最低、信号最快。

## 5. 诚实约束

- 图片必须与真实成品一致（AI 图风格贴近实拍，不生成"永远不可能做出来"的摆拍）。
- 不刷评分、不造假 aggregateRating（见 desktop-serp-benchmark.md §3）。
